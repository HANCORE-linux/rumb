# Contributing to rumb

Thanks for helping. rumb shows what the next update brings and what is already failing, and it only reads. Changes should keep it that way.

## Build and run

```sh
sudo pacman -S --needed git make cargo jq pacman-contrib fakeroot
make
tui/target/release/rumb          # scans this system
tui/target/release/rumb --demo   # plays the bundled demo data
```

`rumb --help` lists the options; `man -l man/rumb.1` shows the manual with the keys.

## Pull requests

- Run the checks that CI runs:
  - in `tui/`: `cargo clippy --locked --release --all-targets -- -D warnings` and `cargo test --locked --release`
  - in the repository root: `shellcheck --severity=warning bin/rumb-scan tui/export-themes`
- Keep one topic per pull request and say what changes for the user.
- Add before/after screenshots for anything visible. The demo data is fine; screenshots of a real system can show private details.
- Write commit messages with a short imperative subject in English, for example "Show the date of older events".
- Releases are made by the maintainer.

## Design

**Design changes are not accepted, only proposals.** Layout, colours, text on screen, the pictures and the eye are decided by the maintainer. To propose a change, open an issue with before/after screenshots.

The screen follows these rules:

- Every text is data, a legend or a key hint. No filler.
- A value that is not known yet stays empty. Nothing is guessed.
- Each fact appears once per screen. A detail window adds information instead of repeating what is visible.
- Colour is a signal only: red means act, yellow means look, the theme accent means problem, green means "belongs to the selected update". Everything else is neutral.
- Text keeps a contrast of at least 4.5:1 in every bundled theme.
- UI text is English, with accurate terms, units and plurals.

## Principles

- **Read-only.** rumb and `rumb-scan` never ask for root and never change the system. A test fails if the sources name sudo, pkexec, doas, su or run0, or let `checkupdates` download.
- **Plain Arch first.** Omarchy, Hyprland, nvidia, snapper and AUR helpers are optional. Check that a tool exists before using it, and leave a value empty when it cannot be read.
- **Facts only.** Every number on screen comes from a command that rumb ran.

## Where things are

| Path | What |
|---|---|
| `bin/rumb-scan` | the scanner (bash): a text report, `--json`, or a stream of events for the dashboard |
| `tui/src/app.rs` | the data from the scanner |
| `tui/src/page.rs` | layout and drawing |
| `tui/src/motion.rs` | animation, the gaze of the eye, the pupil text |
| `tui/src/ink.rs` | the pictures: eye, icons, graphs |
| `tui/src/pictures.rs`, `tui/src/sixel.rs` | image output for the terminal |
| `tui/src/export.rs` | the Markdown report (key `e`) |
| `tui/demo.ndjson` | the demo stream |
| `tui/themes.json` | the bundled themes, generated by `tui/export-themes` |
| `man/rumb.1` | the manual |

## Scanner changes

- `bin/rumb-scan` runs with `set -uo pipefail`: initialize variables, quote expansions and keep shellcheck clean.
- A missing or failing command must not stop the scan; report that check as failed instead.
- New data goes into the stream as new fields. The dashboard reads them with `#[serde(default)]` so older streams still load; add them to `tui/demo.ndjson` as well.
